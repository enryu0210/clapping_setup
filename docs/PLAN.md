# 프로젝트 계획서 — Clapping Setup

> 최종 수정: 2026-08-09

## 1. 한 줄 요약

**박수 두 번(짝짝)을 감지해서, 미리 등록한 업무용 프로그램들을 한 번에 실행하는 Windows 백그라운드 앱.**

---

## 2. 왜 만드는가

| 구분 | 내용 |
|------|------|
| 진짜 문제 | 매일 작업 시작할 때 IDE, 브라우저, 메신저, 음악앱을 하나씩 켜는 게 귀찮다 |
| 기존 대안 | 배치 파일(.bat) 만들어서 더블클릭 — 이미 충분히 빠르다 |
| 그럼에도 만드는 이유 | **재미.** 손이 자유롭지 않을 때(커피 들고 앉을 때) 쓸 수 있고, 오디오 신호처리를 직접 다뤄보는 학습 목적 |

> 💡 솔직한 평가: 실용성만 보면 `.bat` 파일이 이깁니다. 이 프로젝트의 진짜 가치는 **"소리로 컴퓨터를 조작한다"는 경험**과 **오탐(잘못 감지) 없이 만드는 기술적 난이도**에 있습니다. 그래서 목표를 "동작한다"가 아니라 **"하루 종일 켜놔도 오작동하지 않는다"**로 잡습니다.

## 3. 기능 범위 (Scope)

### 3.1 꼭 넣을 것 (MVP, v0.1)

- [x] 마이크 입력 실시간 수신
- [x] 박수 2회 감지 (오탐 최소화 로직 포함)
- [x] YAML 설정 파일에 등록된 프로그램 실행
- [x] 콘솔 로그로 감지 여부 확인 (디버깅용)
- [x] **GUI 화면 + 첫 실행 시 마이크 선택** ← 패키징 배포가 목표라 MVP에 포함
- [ ] **exe 패키징** (PyInstaller)

> 📌 GUI와 패키징이 MVP에 들어온 이유: 처음 계획은 콘솔 도구였지만, **배포해서 쓰는 것**이
> 목표로 정해졌습니다. 파이썬을 깔고 명령어를 치게 할 수는 없고, 무엇보다
> **마이크 선택**은 콘솔 옵션으로 넘기기엔 너무 중요합니다(M1에서 확인한 최대 함정).
> 그래서 "첫 실행 = 마이크 고르는 화면"을 기본 경로로 만들었습니다.

### 3.2 넣으면 좋은 것 (v0.2 ~ v0.3)

- [x] 시스템 트레이 아이콘 (켜기/끄기/종료)
- [x] 이미 실행 중인 프로그램은 다시 켜지 않기 (중복 방지)
- [ ] 프로필 여러 개 (`work` / `game` / `study`) — 박수 2번 vs 3번으로 구분
- [x] 민감도 자동 보정 (주변 소음 크기에 맞춰 임계값 조정) — M2/M3의 [박수 보정]으로 대체
- [x] Windows 시작 시 자동 실행

### 3.3 하지 않을 것 (Non-goals)

- ❌ **음성 인식(STT)** — "컴퓨터 켜줘" 같은 명령어 인식은 범위 밖. 박수는 의도적으로 단순한 신호를 쓴다.
- ❌ **머신러닝 모델 학습** — 규칙 기반(신호처리)으로 충분히 정확하게 만드는 게 목표. 모델을 쓰면 배포가 무거워진다.
- ❌ **소리 녹음/저장** — 프라이버시 문제. 오디오는 메모리에서 즉시 분석하고 버린다.
- ❌ **macOS / Linux 지원** — 프로그램 실행 방식이 OS마다 달라서 일단 Windows만.

## 4. 핵심 리스크와 대응

이 프로젝트가 실패한다면 십중팔구 아래 3가지 중 하나 때문입니다.

### 리스크 1: 오탐 (가장 위험) 🔴

**증상:** 키보드 타이핑, 문 닫는 소리, 기침, 책상 두드리는 소리에 반응해서 프로그램 8개가 갑자기 켜짐.

**대응 (4중 필터):**

1. **크기 조건** — 주변 배경 소음 평균보다 훨씬 클 것
2. **모양 조건** — 소리가 순식간에 커졌다가 0.1초 안에 사라질 것 (박수는 "탁", 말소리는 "우우우~")
3. **주파수 조건** — 2kHz 이상 고음 비율이 높을 것 (책상 치는 "쿵"은 저음이라 걸러짐)
4. **간격 조건** — 두 번의 박수 간격이 0.15~0.8초일 것 (한 번만 나는 소리는 무시)

> 예시: 문 닫는 소리 "쾅"은 조건 1·2는 통과하지만 저음이라 3번에서 걸러지고, 한 번만 나므로 4번에서도 걸러집니다.

### 리스크 2: 마이크 점유 충돌 🟡

**증상:** 이 앱이 마이크를 계속 잡고 있어서 화상회의(Zoom, Teams)에서 마이크가 안 잡히거나, 반대로 회의 중 박수 소리에 앱이 켜짐.

**대응:**
- 마이크는 **독점(exclusive) 모드가 아닌 공유 모드**로 연다 → 다른 앱과 동시 사용 가능
- 트레이 아이콘에서 **일시정지** 버튼 제공 (회의 중에는 끄기)
- v0.3에서 "특정 프로그램(zoom.exe 등) 실행 중이면 자동 일시정지" 검토

### 리스크 3: 프라이버시 인식 🟡

**증상:** "이 앱이 내 대화를 녹음하는 거 아냐?"

**대응:**
- 오디오는 **파일로 저장하지 않고**, 네트워크로 **전송하지 않는다**. 메모리 버퍼에서 크기·주파수만 계산하고 즉시 폐기.
- 이 사실을 README와 코드 주석에 명시.
- 트레이 아이콘 색으로 "지금 듣고 있음/멈춤" 상태를 항상 보이게.

### 그 외 자잘한 리스크

| 리스크 | 대응 |
|--------|------|
| 프로그램 경로가 기기마다 다름 | `apps.yaml`을 gitignore 처리, `apps.example.yaml`만 공유 |
| 앱 8개 동시 실행 → 시스템 멈칫 | 설정에 `delay`(실행 간 대기 시간) 옵션 제공 |
| 실행 실패(경로 오타 등) | 하나 실패해도 나머지는 계속 실행, 실패 목록을 로그로 안내 |
| 박수 후 프로그램 실행 중 또 박수 감지 | 발동 후 5초 쿨다운(cooldown) |
| 한글 Windows 콘솔(cp949)에서 이모지·특수문자 출력 시 크래시 | 진입점에서 stdout/stderr를 UTF-8로 강제 (`__main__._force_utf8_console`) — M0에서 실제로 겪어 이미 반영함 |

## 5. 개발 단계 (마일스톤)

각 단계는 **그 자체로 동작하는 결과물**이 나오게 쪼갰습니다.

### M0. 뼈대 만들기 ✅ (현재)
- 폴더 구조, 계획 문서, `.gitignore`, 의존성 목록

### M1. 소리가 들리는지 확인 ✅ (완료)
- 마이크에서 데이터를 읽어 **음량(RMS)을 콘솔에 실시간 출력**
- 산출물: `python -m clap_launcher --level`, `--list-devices`, `--device`
- 테스트 18개 통과 (RMS 계산, dBFS 변환, 미터 그리기)

**M1에서 배운 것 (설계에 반영함):**
1. **장치가 수십 개다.** Windows는 같은 마이크를 드라이버 방식(MME/DirectSound/WASAPI)별로
   따로 보여주고, 오디오 인터페이스·가상 장치까지 섞이면 목록이 30개를 넘는다.
   → `--list-devices` / `--device` 옵션과 설정의 `audio.device` 항목을 추가했다.
2. **기본 입력 장치가 실제 마이크가 아닐 수 있다.** 가상 오디오 장치(Wave Link 등)가
   기본으로 잡혀 있으면, 그 앱이 꺼졌을 때 무음만 들어온다.
   → 음량 미터가 "소리가 거의 안 잡힘"을 감지하면 장치를 바꾸라고 안내하고 종료 코드 2를 반환한다.
3. **16000Hz 모노를 강요하면 안 된다.** 대부분의 장치 기본값은 44100Hz 스테레오다.
   → 원하는 사양을 먼저 시도하고 안 되면 장치 기본값으로 물러서는 '협상' 방식으로 구현했다.
   실제 사용된 사양(`StreamSpec`)을 뒷단에 넘겨 그 값으로 계산하게 한다.

### M1.5. GUI + 마이크 선택 화면 ✅ (완료)
- Tkinter 기반 창, 초기 화면에서 마이크 선택, 메인 화면에서 상태 표시
- 고른 마이크는 `%LOCALAPPDATA%\ClappingSetup\settings.json`에 저장
- 테스트 41개 통과 (설정 저장/복구, 막대 계산 등) + 창 스모크 테스트

**여기서 정한 것:**
- **Tkinter 채택** — 표준 라이브러리라 추가 의존성이 0개고, exe로 묶을 때 가장 가볍다.
  (PySide6/Qt는 exe가 100MB를 넘고 라이선스도 신경 써야 한다)
- **소리가 확실히 잡힌 마이크만 '사용하기' 버튼이 열린다** — 무음만 나오는 가상 장치를
  고르고 넘어가는 사고를 입구에서 막는다.
- **설정 파일을 둘로 분리** — 사람이 편집하는 `apps.yaml`(주석 보존)과
  프로그램이 저장하는 `settings.json`(쓰기 가능한 사용자 폴더). 자세한 내용은 ARCHITECTURE.md.

**실제 사용 중 나온 문제와 수정:**
- **Ctrl+C 로 끄면 traceback이 쏟아졌다.** 터미널에서 Ctrl+C 는 정상적인 종료 방법인데
  파이썬 오류 화면이 나오니 프로그램이 고장 난 것처럼 보인다.
  → `KeyboardInterrupt` 를 받아 "종료합니다."만 출력하고, 어떤 경로로 끝나든
  `finally` 에서 마이크를 놓아주도록 고쳤다(안 그러면 마이크를 붙잡은 프로세스가 남는다).
- **창이 터미널 뒤에 열릴 수 있다.** 아무 일도 안 일어난 것처럼 보여서 Ctrl+C 를 누르게 된다.
  → 시작할 때 잠깐 '항상 위'로 올렸다가 바로 풀어준다.

### M2 + M3. 박수 감지 (1회 판별 + 짝짝) ✅ (완료)
- 5가지 특징으로 판별: 음정·평탄도·고음비율·날카로움·길이
- 짝짝 간격 판정 + 쿨다운
- 화면에 **걸러진 이유까지** 실시간 표시, **보정(calibration)** 기능
- 테스트 76개 통과 (리미터를 건 스트림 포함)

**여기서 계획을 크게 바꿨습니다 — 원래 설계가 틀렸습니다:**

처음 계획서(3.1절)는 "배경 소음보다 6배 크면 박수"라는 **크기 기반** 판정이었습니다.
그런데 사용자의 마이크에 **클리핑 가드(리미터)** 가 걸려 있다는 점이 드러나면서
이 방식이 성립하지 않는다는 게 확인됐습니다. 리미터는 큰 소리를 눌러버려
"얼마나 큰가"를 의미 없게 만들고, 첫 박수 뒤 볼륨이 줄어드는 펌핑 때문에
**두 번째 박수를 놓치게** 만듭니다.

그래서 판정 근거를 전부 **크기 → 모양(비율)** 으로 바꿨습니다.
비율은 소리 전체에 몇을 곱해도 변하지 않으므로 리미터를 견딥니다.
실측으로 검증했고(DETECTION.md 1장 표), 리미터를 건 스트림으로 테스트를 고정했습니다.

**실측하고 나서야 알게 된 것들:**
- **종이 구기는 소리는 박수와 지문이 판박이다** (고음·평탄도·ZCR 전부 일치).
  유일한 차이가 길이(25ms vs 110ms)라, '지속 시간' 조건이 필수임을 확인했다.
- **키보드는 박수보다 오히려 더 평탄했다.** 박수는 오므린 손바닥이 울림통 역할을 해서
  스펙트럼에 굴곡이 생긴다. 그래서 평탄도에 **상한**을 추가했다.
- **손가락 튕기기는 구분 불가.** 물리적으로 같은 종류의 소리다. 솔직히 인정하고 넘어간다.
- **보정 중 조건을 다 열었더니 주변 소음이 샘플로 수집됐다.** 느슨하되 완전히 열지는 않은
  울타리 + 최소 크기 조건으로 바꿨다.
- **보정이 오히려 오탐을 늘렸다.** 박수 샘플만 보고 기준을 넓히다 보니, 고음을 덜 잡는
  마이크에서는 넓어진 틈으로 키보드가 통째로 들어왔다(재현: 키보드 5/5 통과).
  → 보정을 2단계로 바꿨다. 1단계 박수(이건 박수다) + 2단계 잡음(이건 아니다).
    경계선을 두 무리 **사이**에 긋는다. 더불어 '소리 길이 하한'을 추가했다
    (박수 26ms vs 키보드 10ms — 박수는 부딪힌 뒤 잠깐 울리지만 딸깍은 안 울린다).
- **잡음이 박수 옆에 붙으면 경계가 박수를 옥죄었다.** `길이 24~30ms` 같은 좁은 창이
  만들어졌다. 관측값 주변에 최소 여유를 강제로 남기게 했다(→ `22~42ms`).
- **몇 초 뒤 로그가 조용히 멈추는 버그.** 모니터는 최근 12개만 들고 있는데 화면이
  "어디까지 봤는지"를 목록 **길이**로 세고 있었다. 12개를 넘으면 길이가 안 변해서
  화면이 "새 이벤트 없음"으로 착각했다. 누적 개수 기준으로 바꾸고, 계산을 순수 함수로
  분리해 창 없이 테스트할 수 있게 했다(`take_new_events`).

### M3.5. 듣는 시간 제한 ✅ (완료) — **설계의 방향을 바꾼 결정**

실사용에서 "타이핑에 반응한다"가 반복되면서, 감지 알고리즘을 더 정교하게 만드는 것만으로는
한계가 있다는 판단이 섰습니다. 손가락 튕기기는 물리적으로 구분이 안 되고,
기계식 키보드도 아슬아슬합니다.

**그래서 문제를 다시 정의했습니다. 이건 정확도 문제가 아니라 확률 문제입니다.**

```
오탐 확률이 시간당 1%라면
  하루 8시간 듣기      → 하루 8% 확률로 오작동
  하루 5분씩 3번 듣기  → 하루 0.25% 확률      (30배 이상 차이)
```

감지기를 30배 정확하게 만드는 것보다 **듣는 시간을 30배 줄이는 게 훨씬 쉽습니다.**

- 평소에는 **마이크를 아예 열지 않는다** (대기 중)
- 듣기 시작: 화면 잠금 해제 / 사용자가 직접 시작
- 듣기 종료: 박수 감지해서 실행 / 시간 초과(기본 5분) / 사용자가 직접 중지
- 잠금 감지는 Windows API를 1.5초마다 물어보는 방식 (창 핸들·메시지 루프가 필요 없어 단순)

**덤으로 얻은 것:** 평소에 마이크를 잡지 않으므로 화상회의와 충돌하지 않고,
프라이버시 걱정도 구조적으로 해소된다. M5에서 넣으려던 '일시정지' 기능도 필요 없어졌다.

**테스트:** 화면을 실제로 잠갔다 푸는 것과 5분을 기다리는 것은 자동화가 불가능하므로,
판단 로직만 순수 함수로 떼어내 값으로 검증한다(`LockWatcher`, `ListeningSession`).
특히 **"프로그램 시작 직후에는 잠금 해제로 오인하지 않는다"** 를 못 박아뒀다.

### M4. 프로그램 실행 연결 ✅ (완료) — **박수 → 실제로 앱이 켜진다** 🎉
- `apps.yaml` 파싱·검증(`config.py`) + type별 실행(`launcher/app_launcher.py`)
- 박수 감지 → 마이크 반납 → 실행 → 결과를 화면에 표시
- 박수 없이 확인하는 콘솔 옵션 `--check-config`, `--launch-apps`
- 테스트 249개 통과 (설정 오류 시나리오, 실패 격리, 화면 연결)

**여기서 정한 것과 그 이유:**

- **설정 오류는 박수를 치기 전에 알린다.** 창을 켤 때 한 번 읽어보고 문제가 있으면
  화면 아래에 바로 띄운다. 박수를 친 바로 그 순간에 "설정 파일이 없습니다"가 뜨면
  가장 김이 새는 순간에 김이 샌다.
- **오타 난 설정 항목은 오류로 처리한다.** `max_harmonicty`(i 빠짐)처럼 한 글자 틀린 항목을
  조용히 무시하면 "설정을 바꿨는데 왜 안 먹지"로 몇 시간을 날린다.
  단, 프로그램이 저장하는 `settings.json` 쪽은 반대로 관대하게 둔다(항목이 늘고 줄어도 죽지 않게).
- **하한 > 상한 조합을 입구에서 막는다.** 예를 들어 `min_decay_ms: 80` / `max_decay_ms: 60` 은
  어떤 소리도 통과할 수 없는 설정인데, 화면에는 그냥 '걸러짐'으로만 찍혀서 원인을 찾을 수 없다.
- **실행은 별도 스레드에서.** `delay` 옵션 때문에 항목 사이에 몇 초씩 쉬어가는데,
  화면 스레드에서 그대로 기다리면 그동안 창이 얼어붙어 고장 난 것처럼 보인다.
- **마이크를 먼저 놓고 나서 실행한다.** 순서를 바꾸면 프로그램 8개가 켜지는 몇 초 동안
  마이크를 계속 잡고 있게 되고, 그 사이 소리로 또 발동할 여지가 생긴다.
- **자식 프로세스를 떼어놓는다(DETACHED_PROCESS).** 안 그러면 콘솔에서 실행했을 때
  창을 닫는 순간 켜둔 프로그램들이 같이 죽는다.
- **설정 파일 경로를 코드에 박지 않는다.** `프로그램 폴더/config/apps.yaml` →
  `%LOCALAPPDATA%\ClappingSetup\apps.yaml` 순으로 찾는다.
  exe로 묶으면 위치가 달라지고(M6), 기기마다 저장소 경로도 다르기 때문이다.

**아직 남은 것 (알고 넘어가는 한계):**
- 스토어 앱(`store`)은 앱 ID가 틀려도 탐색기가 조용히 앱 목록만 띄우고 오류를 주지 않는다.
  즉 "성공"으로 기록되지만 실제로 안 켜졌을 수 있다.
- 이미 실행 중인 프로그램을 또 켠다(중복 방지는 M5).

### M4.5. 프로그램 설정 화면 + 화면 다듬기 ✅ (완료)

M4까지 오니 "설정 파일을 메모장으로 열어 경로를 적는다"가 남은 가장 큰 걸림돌이었습니다.
경로에 역슬래시를 잘못 쓰거나 들여쓰기가 어긋나면 프로그램이 안 뜨는데, 그때마다 원인을
찾는 게 일이었습니다. **파일을 몰라도 쓸 수 있어야** 배포할 수 있습니다.

- 목록 편집 화면(`ui/apps_page.py`) — 추가·삭제·순서·켜고 끄기, `찾아보기`로 exe 고르기
- 설정 **저장** 기능(`config.save_config`) — 지금까지는 읽기만 했다

**여기서 정한 것 — 원래 규칙을 하나 뒤집었습니다:**

지금까지 "프로그램은 `apps.yaml` 을 절대 쓰지 않는다"였습니다. 덮어쓰면 사용자가 적어둔
설명 주석이 날아가기 때문입니다. 그런데 화면에서 목록을 편집하려면 어딘가에는 써야 합니다.

| 선택지 | 문제 |
|--------|------|
| 목록을 `settings.json` 에 따로 저장 | 설정이 두 군데로 갈라진다. 손으로 `apps.yaml` 을 고쳤는데 화면이 무시하는 상황이 생긴다 |
| `apps.yaml` 을 다시 쓴다 ✅ | 주석이 날아간다 |

**후자를 골랐습니다.** '설정 파일은 하나'가 훨씬 중요하고, 주석 문제는
**직전 파일을 `apps.yaml.bak` 으로 남기는 것**으로 되돌릴 수 있게 했습니다.
화면과 파일 머리말에도 이 사실을 적어 뒀습니다.
감지 기준값·마이크 설정은 그대로 다시 써서 **보정 결과가 날아가지 않게** 했습니다.

**화면이 "자글자글하다"는 문제 — 원인은 두 개였습니다:**

1. **Tk 캔버스에는 안티앨리어싱이 없다.** 선 아이콘의 사선과 원이 계단처럼 보였다.
   → Pillow로 **4배 크게 그린 뒤 축소**해서 이미지로 얹는다. 아이콘 정의 코드는 그대로 두고,
     Tk 캔버스인 척하는 어댑터(`icons._PilCanvas`)만 끼웠다. 뉴모피즘 표면도 3배로 그려 줄인다.
2. **글꼴만 화면 배율을 따라가고 도형은 안 따라갔다.** Tkinter는 글꼴 크기를 '포인트'로
   다루므로 125% 화면에서 자동으로 커지는데, 캔버스에 그리는 도형·여백은 '픽셀'이라
   그대로 있었다. 그래서 **글자만 커지고 아이콘·막대·패널은 쪼그라들어** 보였다.
   → `theme.px()` 를 만들어 화면에 그리는 모든 크기가 이 함수를 지나게 했다.
     96 DPI 화면에서는 배율이 1.0이라 아무 일도 일어나지 않으므로, 개발 PC만 보면
     **이 문제는 눈치채기 어렵다.**

**테스트하다 잡은 실제 버그:** 편집칸이 '어느 항목의 내용인지'를 기억하지 않아서,
목록에서 선택이 먼저 바뀌면 **엉뚱한 항목을 덮어썼다.** 선택 번호가 아니라
'칸을 채운 순간의 번호'를 따로 들고 있게 고쳤다(`_form_index`).
순서를 바꾼 직후에도 같은 문제가 있어 칸을 다시 채우게 했다.

### M5. 트레이 아이콘 + 편의 기능 ✅ (완료)

이제 **켜두면 잊어버려도 되는 프로그램**이 됐습니다. 로그인하면 조용히 트레이에 들어가
있다가, 잠금을 풀면 알아서 듣고, 박수를 치면 아직 안 켜진 것만 켭니다.

- **트레이 아이콘**(`ui/tray.py`) — 창을 닫아도 종료되지 않고 트레이로 내려간다.
  아이콘 색이 곧 상태다(초록=듣는 중, 회색=대기 중). 메뉴: 창 열기 / 듣기 시작·중지 / 종료
- **중복 실행 방지**(`launcher/running_apps.py`) — 이미 켜진 exe는 건너뛴다
- **Windows 시작 시 자동 실행**(`autostart.py`) — 메인 화면 토글로 켜고 끈다

> 📌 **'일시정지'는 넣지 않았습니다.** M3.5에서 "평소에는 마이크를 아예 열지 않는다"로
> 바꾼 뒤로, 회의 중에 양보할 마이크 자체가 없어졌기 때문입니다. 계획에 있다고 그대로
> 만들면 아무도 안 쓰는 버튼이 하나 늘 뿐입니다.

**여기서 정한 것과 그 이유:**

- **트레이 스레드는 화면을 절대 건드리지 않는다.** pystray는 자기 루프를 따로 돌아서,
  메뉴 콜백이 트레이 스레드에서 불린다. 거기서 Tkinter 위젯을 만지면 프로그램이 이유 없이
  멈추거나 죽는다(audio_monitor.py와 똑같은 함정).
  → 트레이는 **할 일을 큐에 넣기만** 하고, 화면 스레드가 50ms마다 꺼내 실행한다.
    덤으로 pystray 없이도 이 부분을 테스트할 수 있게 됐다.
- **`available`(라이브러리가 있다)과 `running`(실제로 떠 있다)을 구분한다.**
  이걸 헷갈리면 트레이를 못 띄운 환경(원격 데스크톱 등)에서 창을 숨겨버려
  **프로그램이 통째로 사라진다.** 창을 숨기는 판단은 반드시 `running` 으로 한다.
- **처음 트레이로 내려갈 때 한 번 알려준다.** 안 그러면 "꺼졌나?" 하고 또 실행하게 된다.
- **자동 실행 상태는 settings.json에 적지 않는다.** 진짜 상태는 Windows 레지스트리이고,
  사용자가 작업 관리자에서 직접 끌 수도 있다. 두 군데에 적으면 어긋났을 때 어느 쪽이
  맞는지 알 수 없어진다. → 화면을 열 때마다 레지스트리를 읽는다.
- **자동 실행에는 `--minimized` 를 붙인다.** 로그인할 때마다 창이 튀어나오면 누구라도
  이 기능을 꺼버린다. 그리고 `python.exe` 가 아니라 **`pythonw.exe`** 로 등록한다
  (검은 콘솔 창이 함께 뜨는 것을 막는다).
- **프로세스 목록은 ctypes로 직접 읽는다.** 목록 하나 보려고 psutil을 넣으면 exe 크기와
  패키징 위험이 함께 는다. `session_lock.py` 에서 이미 쓰던 방식이다.
- **중복 검사는 exe에만 한다.** 웹 주소는 탭을 하나 더 여는 게 자연스럽고,
  스토어 앱은 실행파일 이름을 알 수 없다. 실행파일 **이름**으로만 비교하는 것도
  의도적인 단순화다(전체 경로를 읽으려면 권한이 더 필요하고 실패하는 경우가 많다).
- **조회에 실패하면 '아무것도 안 켜져 있다'로 본다.** 그래야 평소처럼 전부 실행된다.
  조회 실패 때문에 프로그램이 안 켜지는 쪽이 훨씬 나쁘다.

**작업하다 드러난 것:** `on_close()` 가 더 이상 종료가 아니게 되면서, 그걸 부르던
확인용 스크립트가 멈춰버렸다. 종료 경로를 `quit_app()` 으로 따로 두고,
`run_gui` 의 마무리 정리도 그쪽을 부르도록 고쳤다(여기서 트레이로 숨어봐야 소용없다).

### M6. 배포용 exe 만들기 ⬅️ 다음 차례
- PyInstaller로 단일 실행 파일 생성 (`--onefile --windowed`)
- 확인해야 할 것들:
  - `sounddevice`가 쓰는 PortAudio DLL이 exe 안에 제대로 들어가는지 (자동으로 안 잡히면 `--add-binary` 필요)
  - 콘솔 창 없이 띄웠을 때(`--windowed`) `print`가 죽지 않는지 → `console.py`에서 이미 대비함
  - 파이썬이 없는 PC에서 실제로 실행되는지 (제일 중요. 개발 PC에서는 항상 잘 된다)
  - 백신 오탐 — PyInstaller exe는 종종 백신에 걸린다. 서명이 없으면 감수해야 한다
  - **자동 실행 등록이 exe 경로로 바뀌는지** (M5의 `build_launch_command` 가 `sys.frozen` 을 본다.
    개발 중에 등록해 뒀다면 exe 로 옮긴 뒤 다시 등록해야 한다)
  - **pystray 트레이 아이콘이 exe 안에서도 뜨는지**

## 6. 기술 선택

| 항목 | 선택 | 이유 |
|------|------|------|
| 언어 | Python 3.12+ | 오디오/신호처리 라이브러리가 풍부하고 빠르게 실험 가능 |
| 화면(UI) | `tkinter` (표준 라이브러리) | exe로 묶을 때 가장 가볍고 문제가 적다 |
| UI 테마 | 뉴모피즘 (직접 구현) | Tkinter엔 그림자 기능이 없어 그림자 이미지를 만들어 쓴다. `Pillow` 필요 (없으면 납작하게 그려지고 기능은 동작) |
| 아이콘 | 캔버스에 직접 그리는 선 아이콘 | 이모지는 글꼴 따라 깨지고 색·크기를 못 맞춘다. 직접 그리면 에셋도 라이선스도 필요 없다 |
| 오디오 입력 | `sounddevice` | Windows에서 별도 설치 없이 wheel로 바로 됨 (PyAudio는 빌드 이슈 잦음) |
| 신호처리 | `numpy` | RMS·FFT 계산. 무거운 `scipy`는 일단 안 씀 |
| 설정 파일 | YAML (`PyYAML`) | JSON과 달리 **주석을 쓸 수 있어서** 설정 파일에 설명을 넣을 수 있음 |
| 트레이 UI | `pystray` + `Pillow` | 가볍고 Windows 트레이에 잘 붙음 (v0.3에서 도입) |

## 7. 완료 기준 (Definition of Done)

MVP가 "완성됐다"고 말하려면 아래를 전부 만족해야 합니다.

1. 박수 두 번 → 등록한 프로그램이 3초 안에 전부 실행된다
2. **1시간 동안 평소처럼 일할 때 오작동 0회** (타이핑·통화·음악 재생 포함)
3. 감지 성공률 90% 이상 (박수 10번 치면 9번 이상 발동)
4. 설정 파일에 없는 경로가 있어도 프로그램이 죽지 않는다
5. README만 보고 다른 PC에서 처음부터 설치·실행할 수 있다
