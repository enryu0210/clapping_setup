# 구조 설계 — ClapDesk

> 최종 수정: 2026-08-08

## 1. 전체 데이터 흐름

마이크에서 들어온 소리가 프로그램 실행까지 가는 길입니다.

```
🎤 마이크
   │  (16kHz, 모노, 10ms씩 조각내서)
   ▼
[1] AudioListener        오디오 하드웨어에서 조각(frame)을 계속 읽어옴
   │  numpy 배열 (샘플 160개)
   ▼
[2] FeatureExtractor     조각 하나당 숫자 2개만 계산: 음량(RMS), 고음비율
   │  (rms=0.42, high_ratio=0.71)
   ▼
[3] ClapDetector         "이건 박수 피크다" 판단 → 피크 시각을 기억
   │  두 피크 간격이 0.15~0.8초면 발동
   ▼
[4] AppLauncher          apps.yaml 읽어서 프로그램들 실행
   │
   ▼
🚀 VSCode, Chrome, Slack ...
```

**핵심 설계 원칙:** 각 단계는 **바로 앞 단계의 결과만** 알면 됩니다.
`ClapDetector`는 마이크가 뭔지 모르고, `AppLauncher`는 소리가 뭔지 모릅니다.
덕분에 마이크 없이도 가짜 숫자를 넣어서 감지 로직만 따로 테스트할 수 있습니다.

## 2-1. 화면(UI) 구조

### 왜 Tkinter인가

패키징(exe 만들기)이 목표라서 골랐습니다.

| 후보 | 장점 | 단점 | 판정 |
|------|------|------|------|
| **Tkinter** | 파이썬 표준 라이브러리, PyInstaller와 궁합이 좋고 exe가 작다 | 요즘 앱만큼 예쁘진 않다 → 뉴모피즘을 직접 구현해 보완 (아래) | ✅ 채택 |
| PySide6 / Qt | 예쁘고 기능이 많다 | exe가 100MB를 넘고 라이선스를 신경 써야 한다 | ❌ |
| 웹 기반(Electron 등) | 디자인 자유도 최고 | 박수 하나 켜자고 브라우저를 통째로 넣는 셈 | ❌ |

### 뉴모피즘을 Tkinter로 어떻게 만들었나

**Tkinter에는 '그림자'라는 개념이 아예 없습니다.** CSS의 `box-shadow` 같은 게 없어서
버튼 뒤에 흐릿한 그림자를 깔 방법이 기본 기능에는 없습니다.

그래서 **그림자가 그려진 이미지를 직접 만들어** 캔버스에 깔고, 그 위에 글자와 아이콘을 얹습니다.

```
[Pillow로 만든 배경 이미지]   ← 둥근 사각형 + 양쪽 방향 가우시안 블러 그림자
        ↓ 캔버스에 깔기
[캔버스에 그린 아이콘 + 글자]  ← 색을 자유롭게 바꿀 수 있다
```

| 모양 | 만드는 법 |
|------|-----------|
| 튀어나옴(raised) | 도형 뒤에 밝은 그림자(왼쪽 위) + 어두운 그림자(오른쪽 아래)를 깔고 도형으로 덮는다 |
| 들어감(inset) | 도형을 먼저 깔고, **그 안쪽에** 그림자를 그린다. (도형 − 도형을 살짝 민 것) = 한쪽 가장자리 띠 |

이미지는 크기·모양별로 **한 번만 만들어 캐시**합니다. 화면이 20fps로 갱신돼도
매번 다시 만들지 않습니다. Pillow가 없으면 그림자 없이 납작하게 그려지고,
**기능은 그대로 동작합니다.**

### 아이콘은 왜 이모지가 아닌가

처음에는 이모지(👏🎤🎯)를 썼는데 세 가지 문제가 있었습니다.

1. Windows 이모지는 알록달록해서 뉴모피즘의 차분한 톤과 따로 논다
2. 글꼴에 따라 흑백으로 나오거나 아예 네모(□)로 깨진다
3. 크기·색을 마음대로 못 맞춘다

그래서 `ui/icons.py`에서 **캔버스에 선으로 직접 그립니다.** 이미지 파일을 들고 다닐
필요가 없어 패키징이 단순해지고, 라이선스 문제도 없으며, **색을 인자로 받으므로
테마 색이 바뀌면 아이콘 색도 저절로 따라옵니다.**

### 화면 흐름

```
프로그램 시작
   │
   ├─ 마이크를 고른 적 없음 ──→ [초기 화면] 마이크 선택
   │                              고르면 settings.json에 저장
   │                                     │
   └─ 이미 고름 ────────────────────────┴──→ [메인 화면] 상태 표시
                                              '마이크 변경' 누르면 초기 화면으로
```

창은 **하나만** 두고 내용물(페이지)만 갈아끼웁니다. 창을 여러 개 띄우면 작업표시줄이
지저분해지고 창 사이 상태를 주고받기도 번거롭기 때문입니다.

### ⚠️ 스레드 규칙 (GUI에서 가장 흔한 사고)

**Tkinter 위젯은 메인 스레드에서만 건드릴 수 있습니다.** 그런데 마이크 데이터는
오디오 라이브러리가 만든 다른 스레드에서 10ms마다 들어옵니다. 오디오 스레드에서
라벨을 직접 고치면 프로그램이 이유 없이 멈추거나 죽습니다.

그래서 `ui/audio_monitor.py`를 사이에 두고 이렇게 나눴습니다.

```
[오디오 스레드]              [AudioMonitor]           [화면 스레드]
소리 읽기 → 음량 계산  ──쓰기──→  최신 상태 보관  ←─읽기──  50ms마다 읽어서 화면 갱신
                              (Lock으로 보호)
```

둘은 서로를 직접 부르지 않습니다. **오디오 쪽은 쓰기만, 화면 쪽은 읽기만** 합니다.

### 설정 파일이 두 개인 이유

| 파일 | 누가 쓰나 | 위치 | 내용 |
|------|-----------|------|------|
| `config/apps.yaml` | **사람**이 손으로 편집 | 저장소 폴더 | 실행할 프로그램 목록, 감지 민감도 |
| `settings.json` | **프로그램**이 저장 | `%LOCALAPPDATA%\ClapDesk\` | UI에서 고른 마이크 |

나눈 이유가 두 가지입니다.

1. **주석을 지키기 위해서** — `apps.yaml`에는 설명 주석이 잔뜩 들어 있는데, 프로그램이
   YAML을 다시 저장하면 주석이 전부 날아갑니다. 그래서 apps.yaml은 **읽기만** 합니다.
2. **패키징 대비** — exe로 설치하면 프로그램이 `Program Files` 같은 쓰기 금지 폴더에
   들어갑니다. 그 옆에 설정을 저장하려 하면 권한 오류가 납니다. 사용자별 폴더는 안전합니다.

덤으로, 마이크 선택은 **기기마다 다른 값**이라 저장소에 들어가면 안 되는 정보이기도 합니다.

## 3. 박수 감지 알고리즘 (핵심)

### 3.1 박수 소리의 특징

박수는 소리 중에서도 성격이 아주 뚜렷합니다.

| 특징 | 박수 | 말소리 | 문 닫는 소리 | 키보드 |
|------|------|--------|--------------|--------|
| 최대 음량 | 매우 큼 | 보통 | 큼 | 작음 |
| 지속 시간 | **~50ms (순간)** | 300ms 이상 | 100~300ms | 30ms |
| 고음(2kHz+) 비율 | **높음** | 낮음 | 낮음(둔탁) | 중간 |
| 반복 | **2번 연속** | 계속 | 1번 | 계속 |

→ **이 4개를 전부 만족해야 박수**로 인정합니다. 하나라도 어긋나면 무시.

### 3.2 단계별 판정

```
[1단계] 음량 조건
   현재 RMS > (최근 3초 배경소음 평균 × 감도배수)
   ※ 고정값이 아니라 "배경 대비"로 판단 → 조용한 방/시끄러운 카페 모두 대응

[2단계] 지속시간 조건
   임계값 넘은 상태가 120ms 이내에 끝날 것
   → 계속 큰 소리(음악, 대화)는 여기서 탈락

[3단계] 주파수 조건
   2kHz 이상 대역 에너지 / 전체 에너지 > 0.4
   → "쿵"(저음 충격음)은 여기서 탈락

   ┌ 왜 FFT까지 쓰나?
   │  음량만 보면 문 닫는 소리를 절대 못 거릅니다.
   │  박수는 손바닥 사이 공기가 터지는 소리라 고음이 유난히 강합니다.
   └ 조각 하나(10ms)당 FFT 1회면 CPU 부담도 거의 없습니다.

[4단계] 간격 조건
   피크 발생 → 100ms 불응기(같은 박수의 잔향 무시)
             → 150~800ms 안에 두 번째 피크가 오면 🎉 발동
             → 800ms 넘으면 첫 피크 기억을 버림
```

### 3.3 타임라인 예시

```
시간(ms)  0     200        1000
소리      👏    👏         
판정      피크1 피크2       
                └─ 간격 200ms → 조건(150~800ms) 만족 → 🚀 실행!
                              └─ 이후 5초 쿨다운 (실행 중 재발동 방지)
```

```
시간(ms)  0          1500
소리      👏         👏
판정      피크1      (피크1 기억은 800ms에 이미 폐기됨) → 새 피크1
                     → 발동 안 함 ✅ (너무 느린 박수는 우연일 가능성이 큼)
```

### 3.4 튜닝 가능한 값

전부 `apps.yaml`의 `detection` 항목에서 조절합니다. 코드를 고칠 필요 없습니다.

| 값 | 기본값 | 의미 | 올리면 |
|----|--------|------|--------|
| `sensitivity` | 6.0 | 배경소음 대비 몇 배 커야 피크인가 | 둔감해짐(오탐↓, 미감지↑) |
| `min_interval_ms` | 150 | 두 박수 최소 간격 | — |
| `max_interval_ms` | 800 | 두 박수 최대 간격 | 느긋한 박수도 인정 |
| `high_freq_ratio` | 0.4 | 고음 비율 하한 | 저음 소리를 더 확실히 배제 |
| `cooldown_sec` | 5.0 | 발동 후 재감지 금지 시간 | 연속 실행 방지 강화 |

## 4. 각 모듈의 책임

### `config.py`
- `apps.yaml`을 읽어 파이썬 객체로 변환
- **파일이 없으면** 찾아본 경로들과 함께 `apps.example.yaml`을 복사하라고 알려줌
- **문법 오류**면 몇 번째 줄이 문제인지, **필수 항목 누락**이면 몇 번째 항목인지 알려줌
- 값이 비어 있으면 기본값으로 채움
- **경로를 코드에 박지 않는다**: `CLAP_LAUNCHER_CONFIG` → `<프로그램 폴더>/config/apps.yaml`
  → `%LOCALAPPDATA%\ClapDesk\apps.yaml` 순으로 찾는다.
  exe로 묶으면(M6) 기준 폴더가 `sys.executable` 옆으로 바뀌므로 그때그때 계산한다
- ⚠️ **오타에 엄격하다**: 모르는 `detection` 항목은 오류로 처리한다. 사람이 손으로 적는
  파일이라 조용히 무시하면 "바꿨는데 왜 안 먹지"가 된다.
  반대로 프로그램이 저장하는 `settings.json`(`settings.py`)은 모르는 항목을 무시한다 —
  항목이 늘거나 줄어도 예전 파일 때문에 죽지 않아야 하기 때문이다. **의도적으로 다르다.**
- **저장도 한다**(`save_config`, M4.5부터). 원래는 읽기 전용이었지만 화면에서 목록을
  편집하게 되면서 필요해졌다. 덮어쓰기 전에 `.bak` 을 남기고, 임시 파일에 다 쓴 뒤
  이름을 바꿔치기해 도중에 죽어도 파일이 반토막 나지 않게 한다

### `audio/listener.py`
- `sounddevice`로 마이크 스트림 열기 (공유 모드)
- **사양 협상**: 16kHz 모노를 먼저 시도하고, 장치가 거부하면 장치 기본값(보통 44.1kHz 스테레오)으로 물러선다. 실제로 열린 사양은 `StreamSpec`으로 뒷단에 전달 — 뒷단은 16kHz라고 가정하면 안 된다
- **장치 선택**: 번호 또는 이름 일부로 지정 가능. 이름으로 지정하면 USB를 다시 꽂아 번호가 바뀌어도 안전하다
- 오디오 콜백에서는 **복사해서 큐에 넣기만** 한다. 콜백이 늦으면 소리가 끊기므로 계산은 소비 쪽에서
- 콜백으로 들어온 조각을 큐에 넣기
- **마이크가 없거나 권한이 없으면** 원인을 설명하는 예외 발생
- 오디오는 **어디에도 저장하지 않음** (프라이버시 원칙)

### `audio/features.py`
- 조각 → `(rms, high_freq_ratio)` 변환. 상태 없는 순수 함수
- 테스트하기 가장 쉬운 부분: 가짜 사인파를 넣어 값 검증

### `detector/clap_detector.py`
- 위 3장의 4단계 판정 상태기계(state machine)
- 상태: `IDLE`(대기) → `ARMED`(첫 박수 들음) → `COOLDOWN`(방금 발동)
- **시간을 인자로 받는다** (`now: float`) → 테스트에서 시간을 조작해 1초를 0초 만에 검증 가능

### `launcher/app_launcher.py`
- 항목 종류별 실행: 실행파일(`subprocess`) / URL(`webbrowser`) / 폴더(`os.startfile`) /
  Microsoft Store 앱(`explorer.exe shell:AppsFolder\<앱ID>`)
- **하나가 실패해도 나머지는 계속 실행** (경로 오타로 전체가 멈추면 안 됨).
  예상 못 한 예외까지 잡아서 결과에 담는다 — 이 규칙이 이 모듈의 존재 이유다
- 결과 요약 반환: `성공 6개 / 실패 1개 — Slack: 경로를 찾을 수 없습니다: C:\...`
- **자식을 기다리지 않는다**(`wait` 하지 않음). VS Code가 꺼질 때까지 기다리면 본체가 멈춘다
- **자식을 떼어놓는다**(`DETACHED_PROCESS`). 안 그러면 콘솔 창을 닫을 때 켜둔 프로그램이 같이 죽는다
- 실행기(`launchers`)와 대기 함수(`sleep`)를 **밖에서 갈아끼울 수 있다** — 테스트할 때마다
  진짜로 프로그램 8개가 켜지고 delay만큼 진짜로 기다리면 아무도 테스트를 안 돌린다

### `ui/app.py`
- 창 하나를 만들고 페이지를 갈아끼운다
- 50ms마다 현재 페이지에게 "최신 값으로 갱신하라"고 알린다
- 창을 닫을 때 오디오 스레드를 확실히 멈춘다 (안 하면 창은 사라졌는데 프로세스가 남는다)

### `ui/device_page.py` — 초기 화면
- 입력 장치 목록을 보여주고, **고르는 즉시 그 장치로 음량 막대가 움직인다**
- 사용자는 박수를 쳐보고 막대가 튀는 걸 확인한 다음 결정한다
- **소리가 확실히 잡힌 장치만** '이 마이크 사용하기' 버튼이 열린다
  → 무음만 나오는 가상 장치를 고르고 넘어가는 사고를 여기서 막는다

### `ui/main_page.py` — 메인 화면
- 지금 듣는 중인지, 어떤 마이크인지, 음량이 어떤지 항상 보여준다
- 상태를 계속 보여주는 것은 장식이 아니라 **프라이버시에 대한 대응**이다
- 듣기 시작/중지 버튼 (M3.5 이후 '일시정지'는 불필요해졌다 — 평소에 마이크를 아예 안 잡는다)
- **박수 감지 → 프로그램 실행**의 연결 지점. 순서가 중요하다:
  `마이크 반납 → 실행(별도 스레드) → 결과 표시`
  - 마이크를 먼저 놓는 이유: 프로그램 8개가 켜지는 몇 초 동안 마이크를 잡고 있으면
    그 사이 소리로 또 발동할 여지가 생긴다
  - 별도 스레드인 이유: `delay` 만큼 쉬어갈 때 창이 얼어붙으면 고장 난 것처럼 보인다.
    결과 표시는 `after(0, ...)`로 화면 스레드에 넘긴다(위젯은 메인 스레드 전용)
- 설정 파일은 **창을 열 때 한 번**, 그리고 **박수를 칠 때마다** 다시 읽는다.
  앞은 오류를 미리 알려주기 위해, 뒤는 파일을 고친 뒤 프로그램을 껐다 켜지 않아도 되게 하기 위해

### `ui/apps_page.py` — 프로그램 설정 화면
- 실행할 목록을 화면에서 편집한다 (추가·삭제·순서·켜고 끄기·`찾아보기`)
- ⚠️ **저장하면 `apps.yaml` 을 다시 쓴다.** 주석이 사라지는 대신 `.bak` 을 남긴다.
  왜 그렇게 정했는지는 `config.py` 의 '저장' 부분 주석 참고
- `detection`·`audio` 는 읽은 그대로 다시 저장한다 — 목록을 고쳤다고 보정값이 날아가면 안 된다
- ⚠️ 입력칸이 **어느 항목의 내용인지**(`_form_index`)를 선택 번호와 따로 들고 있다.
  선택이 먼저 바뀌는 경로에서 엉뚱한 항목을 덮어쓰는 버그가 실제로 있었다

### `ui/theme.py` — 색·글꼴·화면 배율
- ⚠️ **`px()` 를 거치지 않은 픽셀 값은 고해상도 화면에서 깨진다.**
  Tkinter는 글꼴만 화면 DPI에 맞춰 키워주고(포인트 단위), 캔버스에 그리는 도형·여백은
  픽셀 그대로 둔다. 그래서 125% 화면에서는 글자만 커지고 나머지는 쪼그라들어 보인다
- 96 DPI 화면에서는 배율이 1.0이라 아무 일도 안 일어난다 → **개발 PC만 보면 눈치채기 어렵다**

### `ui/icons.py` — 선 아이콘
- ⚠️ **Tk 캔버스에는 안티앨리어싱이 없다.** 사선과 원이 계단처럼 보인다
- 그래서 Pillow로 4배 크게 그린 뒤 축소해 이미지로 얹는다.
  아이콘 정의(17개+)는 그대로 두고, Tk 캔버스인 척하는 어댑터(`_PilCanvas`)만 끼웠다.
  덕분에 아이콘 코드를 두 벌 관리하지 않는다
- Pillow가 없으면 예전처럼 캔버스에 직접 그린다 (자글자글하지만 동작한다)

### `ui/tray.py` — 트레이 아이콘
- 창을 닫으면 종료하지 않고 트레이로 내려간다. 아이콘 색이 곧 상태다(초록=듣는 중)
- ⚠️ **pystray 는 자기 루프를 따로 돈다.** 메뉴 콜백이 트레이 스레드에서 불리므로,
  거기서 Tkinter 위젯을 건드리면 프로그램이 이유 없이 멈추거나 죽는다
  (audio_monitor.py 와 똑같은 함정) → 큐에 넣고 화면 스레드가 꺼내 실행한다
- ⚠️ `available`(라이브러리가 있다)과 `running`(실제로 떠 있다)은 **다르다.**
  창을 숨기는 판단은 반드시 `running` 으로 한다 — 트레이를 못 띄운 환경에서 숨기면
  프로그램이 통째로 사라진다

### `autostart.py` — Windows 시작 시 자동 실행
- `HKEY_CURRENT_USER\...\Run` 레지스트리에 등록/해제 (관리자 권한이 필요 없다)
- ⚠️ **상태를 settings.json 에 적지 않는다.** 진짜 상태는 레지스트리이고 사용자가
  작업 관리자에서 직접 끌 수도 있다. 두 군데에 적으면 어긋났을 때 답이 없어진다
- 등록되는 명령에는 `--minimized` 가 붙고, `python.exe` 가 아니라 **`pythonw.exe`** 를 쓴다
  (로그인 때마다 창이나 검은 콘솔이 튀어나오면 누구라도 이 기능을 꺼버린다)

### `launcher/running_apps.py` — 중복 실행 방지
- 지금 돌고 있는 프로세스 이름을 ctypes 로 읽는다 (psutil 을 넣지 않기 위해)
- 조회에 실패하면 **빈 집합**을 돌려준다 → '아무것도 안 켜져 있다'로 읽혀 평소처럼
  전부 실행된다. 조회 실패 때문에 프로그램이 안 켜지는 쪽이 훨씬 나쁘다

## 5. 테스트 전략

**마이크 없이 로직을 검증할 수 있어야 한다**가 핵심입니다. 매번 손뼉 쳐서 확인하면 개발이 안 됩니다.

| 대상 | 방법 |
|------|------|
| `features.py` | 사인파(저음/고음)를 numpy로 만들어 넣고 `high_freq_ratio` 확인 |
| `clap_detector.py` | 실제 소리 없이 `(rms, ratio, 시각)` 값만 순서대로 넣어 발동 여부 확인 |
| 오탐 방지 | "긴 큰 소리", "저음 충격음", "너무 느린 두 박수" 시나리오를 테스트로 고정 → 튜닝하다 망가지면 즉시 발견 |
| `config.py` | 깨진 YAML, 필수 키 누락 파일로 에러 메시지 확인 (임시 폴더 + `CLAP_LAUNCHER_CONFIG`) |
| `app_launcher.py` | **가짜 실행기**를 끼워 "무엇을 어떤 순서로 실행했는지"만 확인. 진짜로는 아무것도 안 켠다 |
| `ui/main_page.py` | 가짜 마이크·가짜 실행기로 "박수 감지 → 마이크 반납 → 실행" 연결 확인 |
| `ui/apps_page.py` | 임시 설정 파일로 편집→저장→되읽기. **"고친 내용이 사라지지 않는가"** 가 핵심 |
| `config.save_config` | 저장한 값을 되읽어 같은지(왕복) + `.bak` 백업이 남는지 |
| `settings.py` | 깨진 JSON·형식이 다른 JSON·모르는 항목을 넣어 "죽지 않고 기본값" 확인 |
| `running_apps.py` | 프로세스 이름 비교는 값으로. 실제 조회는 "지금 이 python 이 목록에 있는가"로 확인 |
| `autostart.py` | **임시 레지스트리 키**를 가리키게 해서 진짜 winreg 호출을 검증 (사용자의 Run 키는 건드리지 않는다) |
| `ui/tray.py` | pystray 없이 큐 전달만 검증. 아이콘이 뜨는지는 자동 확인이 불가능하다 |
| `ui/widgets.py` | 값 → 막대 비율 계산은 순수 함수라 창 없이 검증 가능 |

화면 자체(창이 뜨는지, 페이지가 전환되는지)는 자동 테스트가 어려워서, 창을 띄우고
정해진 순서대로 눌러본 뒤 닫는 **스모크 테스트 스크립트**로 확인합니다.

실제 마이크 테스트는 `--level` 옵션(콘솔 음량 미터)으로, 실행 대상 확인은
`--check-config` / `--launch-apps` 로 **박수 없이** 수동 진행합니다.
